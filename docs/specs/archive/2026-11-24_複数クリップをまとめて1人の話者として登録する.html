複数クリップをまとめて1人の話者として登録する

作成日: 2026-11-24 ／ 状態: 完了（2026-11-24 実装・519テスト通過） ／ 対象: 音声特徴データベースへの登録（src/voice_db/・DB管理画面）

1. なぜやるか

今の登録は1ファイル＝1話者で、ファイル名がそのまま話者名になる。 そのため短いクリップを複数持っていても、1本だけ選んで登録するしかない。 実際に入っている登録音声は 1.0〜3.0秒で、前後0.5秒ずつのトリミング後は 田村が0.76秒しか残っていない。話者照合に必要な長さ（目安3秒以上、 安定して欲しいのは5〜10秒）に届いていない。

そこで同じ口調のクリップを複数まとめて投げたら、裏で1本に繋いで登録する 経路を足す。繋ぐのは登録するときの1回だけで、照合時には繋がない。

繋いでよいのは「同じ口調」だけ

埋め込みはファイル全体を時間方向にまとめて1本のベクトルにするため、繋ぐと平均が出る。 通常の声と泣き声を繋ぐと両者の中間に点ができ、どちらにも遠くなる。 口調が違うものは 田村 と 田村_泣き のように 別の話者名で登録する（この仕様書では「同じ口調のまとめ方」だけを扱う）。

2. 決めたこと（確認済み）

論点決定
繋ぐ前の素材クリップDBに残す。あとから同じ口調のクリップを1本足して繋ぎ直せるようにする
同じ話者名が既にあるとき繋ぎ直す。既存の素材に今回の分を足して、全部から作り直す
登録時トリミング（前後0.5秒）の見直し今回はやらない。既存の振る舞いを変える話なので別の仕様書・別コミットにする（規約9）

3. DBの構造

voice_databases/<DB名>/
├── 田村.wav                    ← 繋いだ結果。照合に使われる（今と同じ）
├── 三上.wav
└── _clips/                     ← 素材。照合には使われない
    ├── 田村/
    │   ├── 001_tamura_a.wav
    │   ├── 002_tamura_b.wav
    │   └── 003_tamura_c.wav
    └── 三上/
        └── 001_mikami.wav

_clips/ が照合対象にならないことは既存コードで保証されている。 collect_registry_files（src/diarization/registry.py:107）と list_speakers（src/voice_db/registry.py:148）はどちらも path.is_file() でディレクトリを読み飛ばすため、この2つは変更しなくてよい。

素材ファイル名には 001_ のような連番を付ける。同名のクリップを投げても 上書きされないようにするため、また繋ぐ順番を毎回同じにして結果を再現できるようにするため （順番は埋め込みには影響しないが、同じ入力なら同じファイルになるほうが検証しやすい）。

4. 登録の流れ

  1. DB管理画面で話者名を入力し、クリップを複数選択して「まとめて登録」を押す
  2. クリップを _clips/<話者名>/ へ連番付きで保存する
  3. そのフォルダにある全クリップを 16kHz・モノラルに揃えて連結する
  4. 結果を <話者名>.wav として DB 直下に保存する（既にあれば作り直し）
  5. 画面に「素材 n 本 ／ 合計 m.m 秒」を出す。3秒未満なら注意文を添える

5. 作るもの

5.1 連結の部品: src/common/audio.py に追記

当初は src/voice_db/clip_concat.py を新設する案だったが、 src/common/audio.py が「ffmpeg / ffprobe による音声ファイル操作の共通処理」の置き場として 既に存在し、build_extract_command（組み立て）＋ extract_audio（実行）という まったく同じ形のペアが入っていた。ffmpeg コマンドを組み立てる場所が2か所に分かれるのを 避けるため、連結もここに足す（規約3.3）。連結は声紋DB専用の処理ではないので、共通側に置くのが自然。 現在118行なので、足しても目安の600行には遠い。

ffmpeg を呼ぶ部分と、引数を組み立てる部分を分ける（規約4：ロジックをテストしやすくするため）。

関数入力 → 出力役割
build_concat_command (src_paths: list[Path], dst: Path) -> list[str] ffmpeg のコマンドを組み立てて返すだけ。外部に触らないのでそのままテストできる
concat_audio (src_paths: list[Path], dst: Path) -> None 上のコマンドを subprocess.run で実行する。shell=True は使わずリストで渡す（規約8）

入力ごとに aformat でサンプリングレートとチャンネル数を揃えてから concat する。 揃えないと ffmpeg の concat フィルタが失敗するため。レートとチャンネル数は既存の TARGET_SAMPLE_RATE_HZ = 16000 / TARGET_CHANNELS = 1 を使う。

エラーの扱い（規約6）：

  • クリップが0本 → ValueError（「繋ぐクリップが1本もありません」）
  • 存在しないパス → FileNotFoundError（どのパスが無いかを含める）
  • ffmpeg が失敗 → RuntimeError に包み、ffmpeg の stderr を添える。握りつぶさない

5.3 既存関数の追従（ここが抜けると不整合になる）

関数直す内容理由
rename_speaker _clips/<旧名>/ も _clips/<新名>/ へリネームする 名前を変えたあと素材を足すと、旧名のフォルダが使われて繋ぎ直しが効かなくなる
delete_speaker _clips/<話者名>/ もゴミ箱へ退避する 素材が残ると、同じ名前で登録し直したときに消したはずの古いクリップが混ざる

6. テスト方針（TDD）

ffmpeg は外部コマンドなのでモックの対象（規約1.4）。ただし「本当に繋がるか」を 一度も確かめないのは不安なので、実際に ffmpeg を動かす統合テストを1本だけ入れる。 ffmpeg が無い環境では pytest.mark.skipif でスキップする。

対象正常系境界値異常系
build_concat_command 3本分の入力とフィルタが並ぶ 1本だけでも組み立てられる 0本で ValueError
concat_audio 組み立てたコマンドで subprocess.run が呼ばれる（モック） （統合）実 ffmpeg で2本繋ぐと長さが合計になる ffmpeg が失敗したら stderr 付きで RuntimeError
add_speaker_clips 素材が _clips/ に入り <話者名>.wav ができる 同じ話者名で2回呼ぶと既存素材込みで繋ぎ直される 話者名が空／無効なら ValueError
既存への影響 _clips/ が list_speakers に出ない collect_registry_files にも出ない 改名・削除で _clips/ が取り残されない
Web ルート POST で登録でき一覧に出る 対応外の拡張子は読み飛ばす 話者名が空／クリップ0本で画面にエラー

7. やらないこと

  • 照合ロジックは一切触らない。speaker_identifier.py と埋め込みキャッシュは無変更
  • 「話者ごとに複数ベクトルを持って最短距離を採る」方式は作らない。別の話なので今回は入れない
  • 登録時トリミングの見直し（別仕様書）
  • 閾値の既定値の変更（距離を測ってから決める）
  • クリップの自動選別・音質判定（頼まれていない／YAGNI）

8. 完了の確認方法

田村の同じ口調のクリップを複数まとめて登録し直し、同じ音声でもう一度 Step 1 を流して job.json の candidate_distances を比べる。 繋ぐ前 0.788 から下がっていれば狙いどおり。下がらなければ、登録音声の長さ以外に 原因があることが分かるので、それも成果として記録する。
