5. 処理フロー（作業手順）

フェーズ単位で 「特性テストを書く → 緑を確認 → 移動・分割 → 再度緑を確認 → 報告・承認」 を回す。 各フェーズは独立したコミットにする（規約11.1）。

Phase 0  基盤整備（pytest / ruff / src 骨組み / 純ロジックの特性テスト）
   ↓
Phase 1  common/ + config.py の確立（重複の共通化・print→logger）
   ↓
Phase 2  字幕マッチング（subtitle_matcher / subtitle_exporter）の分割
   ↓
Phase 3  音声処理コア（audio_processor / speaker_identification / transcription_backend）の分割
   ↓
Phase 4  Web アプリ層（app.py）の分割
   ↓
Phase 5  Spark 連携・エントリポイント・README・リンタ全体適用・最終確認

各フェーズの終了時に (a) pytest 全緑の出力、(b) 変更ファイル一覧、 (c) 規約4.1 の残違反箇所 を提示して承認を得る。承認前に次フェーズへ進まない。

6. エラー処理方針

  • 本作業では例外の扱いを変更しない。 既存の except Exception や握りつぶしを見つけても、 振る舞いが変わるため直さない（規約2.1 Refactor 段階では振る舞いを変えない）。該当箇所は一覧にして報告し、別タスクとして提案する。
  • 例外は移動先モジュールでもそのまま送出させる。捕捉位置を変えない。
  • print → ロガー置換は、出力文言と出力タイミングを維持する（規約2.7「ログ出力の文言変更など振る舞いに影響しない変更」に準じる）。 ログレベルは既存の意味に合わせて割り当てる（エラー表示は ERROR、進捗は INFO）。
  • 移動にともなう import 失敗・パス解決の失敗は、フェーズ内のスモークテスト（アプリ起動・CLI --help）で検出する。

#内容影響提案
1 src/spark/client.py はどこからも import されていない。 Spark 運用は現在 Path 1（Spark 上で app.py を動かす）のみで、 Path 2（推論 API）の経路は使われていない。 低。動いていないコードを保守し続けることになる。 Path 2 に進むかを決める。進まないなら削除、進むなら通しの結合テストを足す。
2 ジョブ状態（Web の _JOBS、Spark の JOBS）が プロセス内メモリにある。Web はファイル（job.json）にも書くが、 Spark 側はメモリのみで再起動すると消える。 中。uvicorn を複数ワーカーで起動すると、リクエストごとに別プロセスへ振られてジョブが見つからない。 現在は単一ワーカーなので顕在化していない。 複数ワーカーで運用する予定があるなら、Web と同じくファイル or 外部ストアへ寄せる。
3 文字起こし（Step 1）が同期処理。長尺だと uvicorn のタイムアウトに当たりうる。 中。README に --timeout-keep-alive の調整として既述。 Spark サーバーと同じ「job_id を即返して裏で処理」方式に寄せると根本解決になる。
4 except Exception が全体で33箇所ある。AST で「ログも再送出も返り値も無い」ものを 抽出したところ10箇所該当したが、精査するとすべて 機能検出のフォールバック（古い faiss に omp_set_num_threads が無い、 torch/MPS が無い、CUDA が使えない）か 一時ファイルの後始末で、握りつぶすことが妥当なものだった。 直すべき握りつぶしは無い。 なし。 対応不要。ただし後始末の重複は下記のとおり共通化した。
5 声紋DB の削除（DELETE /api/databases/{name}）は確認なしで即時・不可逆。 GUI 側にも確認ダイアログは無い。 中。誤操作で登録済みの声紋がすべて消える。 削除前の確認、またはゴミ箱ディレクトリへの退避。
6 /process/matching の if not job_id は、値が届かない要求では 到達しない（FastAPI の検証が先に 422 を返す）。ブラウザのフォーム送信では空文字が届くため 案内文も使われるが、経路が二重になっている。 低。特性テストで両方の挙動を固定済み。 422 のときも htmx で読める形に整えるなら、例外ハンドラを足す。
7 /unknowns/{job_id}/clip/{cluster_id} のパス区切り検査（400）は 経路解決の 404 に先を越されるため到達しない。 なし（多層防御として意図的に残置）。 そのままでよい。
