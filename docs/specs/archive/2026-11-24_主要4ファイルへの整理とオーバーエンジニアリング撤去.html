4. ご質問への回答: 4ファイル構成はできるか

できる。今のコードはすでにこの4工程に分かれているので、やるのは「窓口を作って名前を付ける」こと。ただし条件が1つある。

条件: transcription.py と speaker_verification.py は話者分離の結果を共有しなければならない

ご提案どおり「文字起こし」と「話者照合」を完全に独立した入口にすると、 どちらも自分で ffmpeg 変換 → 背景音除去 → pyannote 話者分離をやり直すことになり、 一番重い工程が2回走る（＝処理時間がほぼ倍）。これは「性能を壊さない」に反する。

そこで speaker_verification.py は「pyannote の区間（diarization）と音声を受け取って照合する部品」にする。 ご指定の「pyannoteで取得した区間で照合」という定義そのままで、区間を自分では作らない。 transcription.py が1回だけ分離して、その結果を渡す。

4-1. もう1つの技術的な制約: 名前の衝突

今 src/transcription/ というディレクトリが存在する（Whisper のバックエンド切り替え）。 Python では同じ階層に transcription/ と transcription.py を同居させられないので、 ディレクトリ側を src/whisper_backends/ に改名する。中身は動かさず、import を書き換えるだけ。

6. 壊さないための不変条件（レビュー時のチェック項目）

#守ること理由
1pyannote の話者分離は1素材につき1回だけ一番重い工程。2回走らせたら性能劣化
2ffmpeg 変換と背景音除去も1回だけ。一時WAVを使い回す同上
3subtitle/embedding.py を numpy/faiss/torch より先に import する順序を維持OpenMP の環境変数を設定しているため。順序が変わると落ちる・遅くなる
4埋め込みキャッシュ（embedding_cache/）のキー計算を変えないキーが変わると既存キャッシュが全部ミスになる
5SRT 本文の [話者] 本文 形式を維持窓口3 の SRT 読み込みがこの形式を前提にしている
6出力ファイルの列・時刻表記・ファイル名の既定値を変えない対応表は人が編集する。列が変わると手作業が無駄になる
7Web の Step 1 は非同期ジョブのまま（temp/clusters/<job_id>/job.json）長尺でも接続が切れない現在の挙動を維持
8処理ログが2秒間隔で画面に流れる挙動を維持進捗が見えなくなると実質的な機能低下
