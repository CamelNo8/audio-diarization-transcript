実機テストで見つかった不具合の解消 仕様書

ステータス: 完了（2026-07-28 / アーカイブ済み）
作成日: 2026-07-28
対象リポジトリ: audio-diarization-transcript（ブランチ main / HEAD 8923d1e）
経緯: リファクタリング後の Spark 実機テストで、クライアントが3件の不具合を報告した。

1. 対象の3件と原因

#報告された症状調査で判明した原因
A ラベル付けで範囲を指定してもDBに保存される音が指定前のまま。 原因は2つ。
(A-1) 波形ドラッグが範囲選択になっていない（本命）。
(A-2) 「ラベル付け済み」の試聴が切り出し前の音を返す（確認手段が嘘をつく）。
B ラベル付け後に「トップに戻る」を押すと最初からやり直しになる。 ラベル付け画面は別タブで開かれるのに、リンクが単なる <a href="/">。 そのタブで空のトップ画面を開き直してしまう。
C 「ご視聴ありがとうございました」「はいはいはい」等のハルシネーションが混ざる。 文字起こし結果に対するフィルタが存在しない。空文字の行を落とすだけ。

1-1. A の調査で確定した事実

サーバー側の切り出しは正常。 実ブラウザで開始 3.00 / 終了 6.00 を指定してラベル付けしたところ、 保存された .wav はちょうど 3.0 秒だった。ffmpeg のコマンド組み立て （src/common/audio.py の build_extract_command）も、Spark の ffmpeg 6.1.1 で -ss 3 -to 6 → 3.0 秒になることを確認済み。よってサーバー側は修正不要。

(A-1) ドラッグが範囲選択になっていない。 templates/partials/crop_editor_script.html は ws.on('decode') で クリップ全体（0〜全長）を覆うリージョンを1つ作るだけで、wavesurfer の regions.enableDragSelection() を呼んでいない。そのため波形上のドラッグは 新規選択ではなく既存リージョンの平行移動として解釈される。 リージョンは既に全体を覆っているので、左方向のドラッグは端で頭打ちになり 値は 0.00〜全長のまま＝切り出しなしになる。 一方、画面の説明文は「波形をドラッグするか数値を入力して、保存したい範囲を選択してください」 と書いてあり、UI と実装が食い違っている。クライアントは波形をドラッグしたと回答済み。

裏付け: Spark 上の voice_databases/転スラ/ の5ファイルは、 対応するクラスタ音声と秒数がミリ秒まで一致していた （大賢者 6.024s = clip_SPEAKER_02.wav、スライム 9.113s = clip_SPEAKER_03.wav、 ヴェルドラ 4.675s、三上 3.797s、田村 1.671s）。実際に一度も切り出されていない。

(A-2) 確認に使う試聴が元音声を指している。 templates/partials/unknowns_list.html の「ラベル付け済み」一覧にある <audio> は /unknowns/<job>/clip/<cluster>、 すなわち元のクラスタ音声を指す。DB に保存された切り出し済みファイルではない。 切り出しが成功していてもここでは必ず「指定前の音」が鳴るため、 仮に A-1 を直してもこれを直さないと直ったことを確認できない。

2. 方針（クライアント確認済み）

論点決定
ハルシネーション行の扱い行ごと削除する。削除した内容はログに残す。
判定条件3つとも入れる。①定型フレーズのリスト ②同一文字列の反復検出 ③直前の行と同一テキストの連続
「トップに戻る」タブを閉じる。別タブで開かれた場合のみ。直接URLで開いた場合は従来どおり / へ。

3. 実装内容

3-A. 切り出し範囲の指定を直す

対象: templates/partials/crop_editor_script.html、 templates/partials/unknowns_list.html

  1. ドラッグで範囲選択できるようにする。 regions.enableDragSelection() を有効にし、波形上のドラッグで新しいリージョンを作る。 新しいリージョンができたら古い方を消し、常に1つだけが存在するようにする （region-created で直前のリージョンを remove()）。 region-updated による数値入力への反映は現状のまま使える。
  2. 初期リージョンは作らない。全体を覆うリージョンがあるとドラッグ開始点が 必ずリージョン上になり、移動と区別できなくなるため。 初期状態は「選択なし＝全体を保存」とし、数値入力は空欄にする （サーバー側は空欄を「全体」として扱う既存挙動と一致する）。 ws.on('decode') では max 属性の設定と全長の保持だけを行う。
  3. 「全体に戻す」はリージョンを消して数値を空欄にする挙動に変える。
  4. 数値入力からリージョンを作れるようにする。 リージョンが無い状態で数値が入力されたら、その範囲でリージョンを新規作成する （現状は if (!region) return; で何もしない）。
  5. 説明文を実際の操作に合わせる。 「波形をドラッグして範囲を選択するか、数値を入力してください。選択しなければ全体を保存します。」
crop_editor_script.html は /databases のトリミングでも使われている （initCropEditor をモーダルから呼ぶ）。同じ変更が両方に効く。 /databases 側のサーバー処理（api_trim_speaker）は空欄を「指定なし」として弾くため、 初期リージョンを廃止しても壊れない。

3-A-2. ラベル付け済みの試聴を、実際に保存されたファイルにする

対象: templates/partials/unknowns_list.html、src/web/routes/unknowns.py

「ラベル付け済み」一覧の <audio> の参照先を、 DB に保存された話者ファイル /api/databases/<db>/speakers/<名前>.wav/audio に変える。 このルートは既に存在し、Cache-Control: no-store も付いているのでそのまま使える。

保存先 DB 名はラベル付け時に job["db_name"] へ記録されるので、テンプレートから参照できる。 ただし自動再照合で解決したクラスタ（resolved_method == "auto"）は DB にファイルを追加していない。この場合は既存話者のファイルを指すことになり、 「そのクラスタの音」ではなくなるため、自動解決分は従来どおり元クラスタ音声を指す。 どちらを鳴らしているかがわかるよう、ラベルを添える（手動＝「保存された音声」／自動＝「クラスタ音声」）。

3-B. 「トップに戻る」でやり直しにならないようにする

対象: templates/unknowns.html

リンクにクリックハンドラを付け、window.opener が存在する （＝ Step 1 の結果から別タブで開かれた）場合は window.close() でこのタブを閉じる。 元のタブには Step 1 の結果と Step 2 のフォームがそのまま残っているので、続きから作業できる。 直接URLを開いた場合は window.opener が無いので、従来どおり / へ遷移する。 文言も「← 閉じて元の画面に戻る」に変える。

3-C. ハルシネーション行を除去する

対象: 新規 src/transcription/hallucination.py、 src/diarization/transcript.py、src/config.py

文字起こしセグメントを CSV の行に落とす build_rows() の中で、 本文が空の行を落としているのと同じ場所に判定を挟む。 ここを通れば CSV と、CSV から作る SRT の両方に効く。

判定 ①: 定型フレーズ

正規化（前後空白の除去、記号・句読点の除去、全角記号の統一）したうえで、 リストのいずれかと一致する行を除去する。初期リストは Whisper 日本語の典型的な幻聴を入れる: 

ご視聴ありがとうございました
ご清聴ありがとうございました
ご視聴ありがとうございます
最後までご視聴いただきありがとうございます
チャンネル登録をお願いします
チャンネル登録よろしくお願いします
おわり
END

リストは src/config.py に定数として置き、 環境変数 HALLUCINATION_PHRASES_FILE で外部ファイルを指定すると追記できるようにする （1行1フレーズ。素材ごとに増やせるようにするため。Spark 側でコードを触らず調整できる）。

判定 ②: 同一文字列の反復

「はいはいはい」「あーあーあー」のように、同じ短い単位が繰り返されるだけの行を除去する。 行を最短の繰り返し単位に分解し、単位が 4 文字以下かつ 3 回以上繰り返されて 行全体を構成している場合に幻聴とみなす。 「そうそう」（2回）や、意味のある長い文の繰り返しは残す。

判定 ③: 直前の行と同一のテキストの連続

正規化後のテキストが直前の採用行と同一であるものを除去する。 Whisper のループ暴走で同じ文が延々続く場合に効く。 最初の1回は残す（本当に同じ相槌を2回言った場合との区別がつかないため、 連続 2 回目以降を落とす）。

誤判定のリスクと歯止め。 「はいはいはい」は実際の相槌としてもあり得る。除去した行は必ず logger.info で「どの行を、どの判定で落としたか」を出す。 spark-logs.sh に流れるので、後から誤判定を確認できる。 リストが素材に合わなければ環境変数で調整する。
